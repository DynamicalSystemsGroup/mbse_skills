# Project governance

Dynamical Systems Group hosts this independent collection for use and contribution by OpenMBEE and other systems engineering communities. Hosting does not imply endorsement by OpenMBEE, OMG, INCOSE or any tool vendor.

## Decisions and responsibilities

Contributors propose changes through issues, discussions and pull requests. Repository maintainers review scope, evidence, provenance and compatibility and decide whether to merge. GitHub repository administrators manage access, settings and releases. There is no elected steering committee or formal institutional approval process.

Use an issue or discussion for a new methodology, significant dependency, integration or distribution change before investing in a broad implementation. Record the problem, alternatives, expected artifacts and tradeoffs. Resolve disagreements using reproducible evidence and documented constraints; maintainers explain unresolved decisions in the relevant thread.

## Review and releases

Prefer focused pull requests and an independent review before merging when another maintainer is available. Contributors remain responsible for generated material, license checks and reported test results. AI assistance does not replace review or evidence.

Follow [contributing](CONTRIBUTING.md) for acceptance criteria and [distribution](docs/distribution.md) for releases. A merged change is not a published release or proof of standards conformance. Maintainership changes and compatibility commitments should be documented before they are advertised.

These are collaboration conventions. Required reviews, branch protection and CODEOWNERS assignments are not configured by this document. Decide those settings once reviewers and the hosted checks are established.
