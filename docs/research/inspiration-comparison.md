# Phase 1: transferable patterns for MBSE agent skills

Study date: 10 October 2026. This comparison is based on inspected first-party source at the revisions in [the provenance register](../../references/sources.json), not a claim that these collections were behaviorally evaluated. The three additional checkouts were cloned for reading only. No installer, plugin, hook, MCP server, or upstream test was run during this comparison.

The existing [principles study](skill-collection-principles.md) describes the mechanism choices; the [MBSE source map](mbse-source-map.md) separates normative language rules from engineering practices and supporting research. This document extends the comparison to scientific research, security auditing, CAD, and existing OpenSysML skills.

## Representative evidence and mechanisms

**Matt Pocock:** [domain modeling](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/skills/engineering/domain-modeling/SKILL.md) distinguishes resolving terminology from reading a glossary, creates artifacts when needed, and reserves ADRs for consequential tradeoffs. [Research](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/skills/engineering/research/SKILL.md) requires primary-source findings persisted as Markdown. [Scope](https://github.com/mattpocock/skills/blob/49dd158d1076134a641b33efb035946536778336/SCOPE.md) requires an observed failure and rejects redundant skill proliferation. The manifest installs a selected subset rather than every folder.

**Superpowers:** [writing skills](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/skills/writing-skills/SKILL.md) describes baseline and assisted pressure scenarios and separates mechanical enforcement from judgment. [Verification before completion](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/skills/verification-before-completion/SKILL.md) demands the actual command and inspected result. The [hook configuration](https://github.com/obra/superpowers/blob/bb92a77741419a4ab5f06e711a283343f1ada0c3/hooks/hooks.json) runs a SessionStart handler on startup, clear and compact: availability/bootstrap is a separate concern from the skill's procedure.

**pstack:** [model the domain](https://github.com/cursor/plugins/blob/d73344bee8cf22e53b9d5f4cf5749d38ba38c174/pstack/skills/principle-model-the-domain/SKILL.md) favors structures that remove invalid states and duplicated rules without forcing abstractions. [Prove it works](https://github.com/cursor/plugins/blob/d73344bee8cf22e53b9d5f4cf5749d38ba38c174/pstack/skills/principle-prove-it-works/SKILL.md) favors rerunnable comparisons against real artifacts. These are two useful principles; the full Cursor plugin and agent orchestration are a separate portability commitment.

**Scientific research:** [literature review](https://github.com/K-Dense-AI/scientific-agent-skills/blob/92ace75ac21efe19a620434e0ca4e356081fe807/skills/literature-review/SKILL.md) records queries, search dates, eligibility and unavailable full text, and distinguishes DOI registration from claim support. Its `verify_citations.py` checks registration and retrieves metadata; it cannot establish that the paper supports a modeling claim. [Uncertainty and units](https://github.com/K-Dense-AI/scientific-agent-skills/blob/92ace75ac21efe19a620434e0ca4e356081fe807/skills/uncertainty-and-units/SKILL.md) requires a measurement model, unit-aware boundaries, correlations, uncertainty assumptions and magnitude checks. These complement a rover budget: a correct unit calculation still needs valid power/mission assumptions. Bundled scripts and `tests/skill-requirements.toml` expose a useful separation between executable helper tests and reasoning guidance.

**Security auditing:** [spec-to-code compliance](https://github.com/trailofbits/skills/blob/442fc9d6c89b1e937e6f7a477e7071ea75fcbea4/plugins/spec-to-code-compliance/skills/spec-to-code-compliance/SKILL.md) routes a workflow rather than asking one context to assert exhaustive checking. Inspected supporting files include `workflows/spec-compliance.js`, an analysis-format reference, checker-agent instructions, and fixtures for contradiction, unsupported naming inference and routing. [False-positive checking](https://github.com/trailofbits/skills/blob/442fc9d6c89b1e937e6f7a477e7071ea75fcbea4/plugins/fp-check/skills/fp-check/SKILL.md) begins with an exact claim, trigger, impact and context, then distinguishes standard/deep verification. In MBSE, a reported engine defect needs the model, library baseline, expected rule and reproduction; diagnostic wording alone is insufficient.

**CAD:** the [recorded README](https://github.com/wogokoro/Agentic-CAD-Skills/blob/2fe1aba0743708ce8e379d47277f13985596dcab/README.md) proposes procedural skills, tool schemas, transport and postconditions as distinct layers. The inspected Git tree contains no substantive skill examples. Treat this as a useful taxonomy, not a tested implementation reference.

**OpenSysML:** the [packaging README](https://github.com/Open-MBEE/OpenSysML/blob/714c459fe5dcce1affb62fd98309b63626dfa311/packaging/agent-skills/README.md) distinguishes using the engine from contributing to it and documents copying/symlinking skill directories. The [modeling skill](https://github.com/Open-MBEE/OpenSysML/blob/714c459fe5dcce1affb62fd98309b63626dfa311/packaging/agent-skills/skills/sysml-v2-modeling/SKILL.md) and [CLI skill](https://github.com/Open-MBEE/OpenSysML/blob/714c459fe5dcce1affb62fd98309b63626dfa311/packaging/agent-skills/skills/opensysml-cli/SKILL.md) cover standard-library imports, validate-first execution, strict portability checks, check verdicts and machine-readable output. These are implementation guidance, not a substitute for an OMG clause or cross-engine test.

## Adopted pattern rationale

| Decision | Mechanism in this repository | Observable result |
| --- | --- | --- |
| Adopt focused task responsibilities | Six skills with explicit triggers, outputs and exclusions; references loaded when needed | Relevant tasks select the needed procedure; unrelated tasks do not invoke it |
| Adopt source and artifact provenance | Versioned standards references, repository SHA/license register, run metadata and raw outputs | Reviewer can recover source identity and the model/tool/library revision |
| Adopt expected-result-first modeling | Hand-calculated oracle plus failing and passing cases | A demonstrated red/green transition and an expectation independent of engine output |
| Adapt specification auditing | Requirement, model expression, expected outcome and observed verdict remain distinguishable | A missing value or unsupported operation cannot silently become a passed check |
| Adapt scientific research practices | Search ledger, source identity, claim-support assessment and explicit access gaps | A DOI/URL alone cannot establish a supported claim or complete review |
| Adapt physical reasoning | Typed quantities, units, bounds, assumptions and finite candidate objective | Feasibility and optimum within the enumerated set are reported separately |
| Adopt mechanical checks as scripts | Collection/link validation and thin engine/LSP adapters | Rerunnable exit status and retained diagnostic evidence |
| Leave hooks/MCP/plugin distribution for later | Portable skill directories and explicit local commands first | No automatic client activation or extra service dependency |

Use a **skill** for judgment or professional procedure; a **reference** for detailed knowledge; a **script** for a repeatable operation; **LSP** for revision-aware language services; **MCP** when a shared tool/data protocol adds concrete value; a **hook** for an authorized lifecycle action; and a **plugin** for packaging proven components for a known host. No transport or packaging mechanism creates engineering validity on its own.

The six starter responsibilities are hypotheses informed by the requested workflow and known failure modes, rather than six empirically established improvements. Only baseline-versus-assisted runs can justify improvement claims. Initial evaluations should cover mistaken v1 notation, invented authority, missing imports/values, dimensional errors, infeasible constraints, overclaimed optimality and irrelevant activation.

## Revisions, licensing and reproducibility

The manifest records the three original revisions plus scientific skills `92ace75ac21efe19a620434e0ca4e356081fe807`, Trail of Bits `442fc9d6c89b1e937e6f7a477e7071ea75fcbea4`, CAD `2fe1aba0743708ce8e379d47277f13985596dcab`, and nearby OpenSysML `714c459fe5dcce1affb62fd98309b63626dfa311`. The OpenSysML checkout is reused from the neighboring standards-research workspace, not vendored here.

Licenses inspected: MIT for Matt Pocock, Superpowers, pstack and K-Dense; CC-BY-SA-4.0 for Trail of Bits; Apache-2.0 for CAD and OpenSysML. This comparison paraphrases and links source principles. No upstream skill prose or helper script is copied into the starter. Any future copying needs appropriate notices and compatible licensing; the collection's MIT license cannot replace third-party terms.

During this pass, `ctxcheck` confirmed DSG context and the 1Password SSH agent; existing unrelated parent-workspace modifications were preserved. The three new clones used `git@github.com-dsg` with `--depth 1`. Clone identities, clean state, license presence and manifest JSON were checked. Findings are from representative source inspection, not exhaustive audits; none of the seven collections' installation workflows, integrations or behavioral tests were executed here.
