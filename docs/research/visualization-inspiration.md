# Visualization principles inspired by Archify

The user selected [Archify](https://github.com/tt-a1i/archify) as inspiration. The installed package declares release 3.0.1, MIT, with skill frontmatter version 3.0. Inspected instructions, authoring defaults, repository-evidence guidance and delivery contract are identified by hashes in the [source record](../../references/visualization-sources.json). No renderer or template was copied; this is original adaptation.

| Adopted idea | MBSE adaptation |
| --- | --- |
| Choose a view by its question | Separate architecture, workflow, sequence/state and numeric comparison; preserve a user's chosen format |
| Attach source identity to meaning | Map material nodes, arrows or plotted points to artifacts and revisions; distinguish proposals and observed evidence |
| Preserve topology during layout repair | Keep IDs, labels, endpoints and mapped claims stable; review a semantic change separately |
| Retain candidate and generated artifact | Keep editable `.mmd`/`.dot`/`.excalidraw`, code/spec and data with exports |
| Separate delivery evidence | Record structural checks, actual native rendering/import, browser checks and perceptual inspection independently |
| Bound a completion claim | A readable view does not establish requirement satisfaction, model conformance or physical adequacy |

Archify's full schema validation, browser gates, update-awareness system, motion, export runtime and recovery transactions remain its own capabilities. Our helpers do not claim equivalent quality gates. Styling and interactivity can aid exploration, but neither is a core systems-engineering dependency.

The [existing-skills review](visualization-skill-discovery.md) changes the implementation choice: keep MBSE-specific adapters and reuse existing tool skills when available, rather than creating general-purpose Mermaid, UML or Excalidraw renderers.
